# Delivery Note System Implementation Plan

## Overview

This document describes **HOW** to implement the Delivery Note system as specified in `delivery-service-spec.md`. It includes technical architecture decisions, tech stack, database schema details, implementation phases, and testing strategies.

## Architecture Decision

### New Microservice: DeliveryService

**Decision**: Create a new standalone microservice called `Maliev.DeliveryService`

**Rationale**:
1. **Domain Separation**: Delivery logistics is a distinct domain from order management and purchasing
2. **Cross-Service References**: DeliveryNote needs to reference BOTH OrderService orders AND PurchaseOrderService purchase orders
3. **Independent Scaling**: Delivery operations may have different performance characteristics than other services
4. **Clear Boundaries**: Follows established Maliev microservices pattern (25+ existing services)
5. **Future Extensibility**: Easier to add shipping integrations, tracking APIs, and logistics features without affecting other services
6. **Team Autonomy**: Separate service allows dedicated team ownership of delivery workflows

**Alternatives Considered**:
- ❌ **Extend OrderService**: Would couple delivery logic to order management, violates single responsibility
- ❌ **Extend PurchaseOrderService**: Same coupling issue, plus doesn't handle customer orders
- ❌ **Shared Library**: Would not provide independent API, database, or deployment

### Sequential ID Generation

Delivery note IDs follow the format: `DN-YYYY-XXXXXX` (e.g., `DN-2026-000001`)

**Implementation**:
```csharp
public class DeliveryNoteIdGenerator
{
    private readonly DeliveryDbContext _context;

    public async Task<string> GenerateNextIdAsync(CancellationToken ct = default)
    {
        var currentYear = DateTime.UtcNow.Year;
        var prefix = $"DN-{currentYear}-";

        // Find the last ID for this year
        var lastId = await _context.DeliveryNotes
            .Where(dn => dn.DeliveryNoteId.StartsWith(prefix))
            .OrderByDescending(dn => dn.DeliveryNoteId)
            .Select(dn => dn.DeliveryNoteId)
            .FirstOrDefaultAsync(ct);

        int nextNumber = 1;
        if (lastId != null)
        {
            var numberPart = lastId.Substring(prefix.Length);
            if (int.TryParse(numberPart, out int currentNumber))
            {
                nextNumber = currentNumber + 1;
            }
        }

        return $"{prefix}{nextNumber:D6}";
    }
}
```

**Concurrency Handling**:
- Use database transaction with serializable isolation level when generating IDs
- Retry logic for race conditions (up to 3 attempts)
- Alternative: Use PostgreSQL sequence with custom formatting

### Key Business Logic

#### Validation Logic

```csharp
private void ValidateCreateRequest(CreateDeliveryNoteRequest request)
{
    if (request.OrderId == null && request.PurchaseOrderId == null)
    {
        throw new ValidationException("Must specify either OrderId or PurchaseOrderId");
    }

    if (request.Items == null || !request.Items.Any())
    {
        throw new ValidationException("Delivery note must have at least one item");
    }

    foreach (var item in request.Items)
    {
        if (item.QuantityDelivered <= 0)
        {
            throw new ValidationException($"Quantity delivered must be positive for item {item.ProductCode}");
        }

        if (item.QuantityDelivered > item.QuantityManufactured)
        {
            throw new ValidationException(
                $"Cannot deliver more than manufactured quantity for item {item.ProductCode}. " +
                $"Manufactured: {item.QuantityManufactured}, Delivered: {item.QuantityDelivered}");
        }
    }
}
```

#### Status Transition Validation

```csharp
private void ValidateStatusTransition(DeliveryStatus currentStatus, DeliveryStatus newStatus)
{
    if (currentStatus == newStatus)
    {
        return; // No change
    }

    var validTransitions = new Dictionary<DeliveryStatus, List<DeliveryStatus>>
    {
        { DeliveryStatus.Pending, new() { DeliveryStatus.InTransit, DeliveryStatus.Cancelled } },
        { DeliveryStatus.InTransit, new() { DeliveryStatus.Delivered, DeliveryStatus.PartiallyDelivered, DeliveryStatus.Cancelled } },
        { DeliveryStatus.PartiallyDelivered, new() { DeliveryStatus.Delivered, DeliveryStatus.Cancelled } },
        { DeliveryStatus.Delivered, new() }, // Terminal state
        { DeliveryStatus.Cancelled, new() }  // Terminal state
    };

    if (!validTransitions[currentStatus].Contains(newStatus))
    {
        throw new InvalidOperationException(
            $"Cannot transition from {currentStatus} to {newStatus}");
    }
}
```

```csharp
using Asp.Versioning;
using Microsoft.AspNetCore.Mvc;

namespace Maliev.DeliveryService.Api.Controllers;

[ApiController]
[ApiVersion("1.0")]
[Route("delivery/v{version:apiVersion}/[controller]")]
[Produces("application/json")]
public class DeliveryNotesController : ControllerBase
{
    private readonly IDeliveryNoteService _deliveryNoteService;
    private readonly IDeliveryNoteAuthorizationService _authorizationService;
    private readonly ILogger<DeliveryNotesController> _logger;

    public DeliveryNotesController(
        IDeliveryNoteService deliveryNoteService,
        IDeliveryNoteAuthorizationService authorizationService,
        ILogger<DeliveryNotesController> logger)
    {
        _deliveryNoteService = deliveryNoteService;
        _authorizationService = authorizationService;
        _logger = logger;
    }

    /// <summary>
    /// Create a new delivery note
    /// </summary>
    [HttpPost]
    [ProducesResponseType(typeof(DeliveryNoteResponse), StatusCodes.Status201Created)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    [ProducesResponseType(StatusCodes.Status403Forbidden)]
    public async Task<ActionResult<DeliveryNoteResponse>> CreateDeliveryNote(
        [FromBody] CreateDeliveryNoteRequest request,
        CancellationToken ct)
    {
        // Authorization check
        var principalId = User.GetPrincipalId();
        if (!await _authorizationService.CanCreateDeliveryNoteAsync(principalId, request.OrderId, ct))
        {
            return Forbid();
        }

        var result = await _deliveryNoteService.CreateDeliveryNoteAsync(request, principalId, ct);

        return CreatedAtAction(
            nameof(GetDeliveryNote),
            new { deliveryNoteId = result.DeliveryNoteId },
            result);
    }

    /// <summary>
    /// Get delivery note by ID
    /// </summary>
    [HttpGet("{deliveryNoteId}")]
    [ProducesResponseType(typeof(DeliveryNoteResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<ActionResult<DeliveryNoteResponse>> GetDeliveryNote(
        [FromRoute] string deliveryNoteId,
        CancellationToken ct)
    {
        var result = await _deliveryNoteService.GetDeliveryNoteAsync(deliveryNoteId, ct);

        if (result == null)
        {
            return NotFound();
        }

        // Authorization check
        var principalId = User.GetPrincipalId();
        if (!await _authorizationService.CanAccessDeliveryNoteAsync(principalId, result.CustomerId, ct))
        {
            return Forbid();
        }

        return Ok(result);
    }

    // Additional endpoints...
}
```

## Risk Mitigation

### Risk: Concurrent ID Generation Collisions
**Mitigation**:
- Use database transaction with serializable isolation
- Implement retry logic (up to 3 attempts)
- Consider PostgreSQL sequence with custom formatter

### Risk: EF Query Filter Performance
**Mitigation**:
- Add indexes on frequently filtered columns
- Use `IgnoreQueryFilters()` when soft-deleted data needed
- Monitor query performance with OpenTelemetry

### Risk: MassTransit Event Ordering
**Mitigation**:
- Use message scheduling for delayed processing
- Implement idempotent event handlers
- Store event history for debugging

### Risk: Cross-Service Data Consistency
**Mitigation**:
- Use eventual consistency via events
- Implement compensating transactions for failures
- Monitor event processing latency
