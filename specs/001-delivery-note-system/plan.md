## Summary

Create a new standalone microservice called `Maliev.DeliveryService` to manage formal delivery notes (ใบส่งของ) for shipments from factory to customers. The system tracks delivered quantities, generates Thai/English bilingual PDFs, manages partial deliveries, and integrates with existing OrderService, PurchaseOrderService, and NotificationService. This implements customer-scoped authorization, graceful degradation for service failures, full observability with OpenTelemetry, 7-year data retention with archival, and URL path-based API versioning.

## Database Schema Overview

**Tables**:
- `delivery_notes`: Main delivery document (PK: delivery_note_id VARCHAR(50) "DN-YYYY-XXXXXX")
- `delivery_note_items`: Line items with ordered/manufactured/delivered quantities
- `delivery_note_files`: Attached files (signatures, photos, packing lists)
- `addresses`: Shipping address snapshots

**Key Patterns**:
- Soft delete with `is_deleted` boolean and query filters
- Optimistic concurrency with `row_version` serial
- Denormalized address snapshot for historical audit trail
- Partial indexes on filtered columns (WHERE NOT is_deleted)
- Sequential ID generation with transaction isolation

## Service Integration Strategy

**Graceful Degradation with Retry**:
- Core operations (create, update status, view) succeed even when non-critical services fail
- Automatic retry with exponential backoff for failed integrations
- User notifications for partial failures ("Delivery note created but customer notification pending")
- Database transactions ensure data integrity regardless of service failures

**Event-Driven Integration**:
- Publish `DeliveryNoteCreatedEvent`, `DeliveryStatusChangedEvent`, `DeliveryCompletedEvent`
- Consume `OrderCompletedEvent` for automatic delivery note drafts (optional)
- Queue failed events for retry with eventual consistency

## Security & Authorization

**Customer-Scoped Access Control**:
- Users can only access delivery notes for assigned customers
- Role-based permissions: Delivery.Read, Delivery.Create, Delivery.Update, Delivery.UpdateStatus, Delivery.Delete, Delivery.UpdateFiles, Delivery.GeneratePdf
- Integration with IAMService for authentication and tenant/customer assignments

## Observability Strategy

**Structured Logging**:
- All operations emit JSON logs with operation type, user, timestamp, delivery note ID, outcome
- Log aggregation for efficient querying and troubleshooting

**Metrics**:
- Request counts, error rates, operation latencies
- Active delivery note counts by status
- Real-time dashboards and alerting

**Distributed Tracing**:
- Trace correlation across DeliveryService, OrderService, PdfService, NotificationService
- 100% trace completeness for delivery note workflows
- Performance bottleneck identification

## Data Retention & Archival

**7-Year Retention with 2-Year Archival Threshold**:
- Active storage: Last 2 years (fast access <2s)
- Archival storage: 3-7 years old (acceptable degradation <5s)
- Automatic deletion after 7 years with audit logging
- Idempotent archival with retry on failures

## API Versioning

**URL Path Versioning**: `/delivery/v1/delivery-notes`, `/delivery/v2/delivery-notes`
- Multiple concurrent versions during transitions
- Minimum 6-month deprecation notice
- Supports gradual client migration
